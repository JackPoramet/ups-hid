# 🛠️ UPS Telemetry Issues & Validation Plan

เอกสารนี้รวบรวมรายการปัญหา (Issues) ที่พบเกี่ยวกับข้อมูล Telemetry ของ UPS และแผนการตรวจสอบ (Validation Plan) เพื่อหาข้อมูลที่ถูกต้องที่สุด โดยอาศัยการดึงข้อมูลดิบระดับฮาร์ดแวร์ (Raw HID Reports) มาเทียบเคียง

---

## 📋 ปัญหาปัจจุบัน (Current Issues)
ปัจจุบันพบปัญหาข้อมูลเพี้ยนในบางรุ่น เนื่องจากแต่ละรุ่นใช้ Offset หรือการจัดเรียงไบต์ (Endianness) ไม่เหมือนกัน:
1. **Offline UPS 2000D / MEC:**
   - `ups.load` แสดงค่า 19-21 ตลอดเวลา แม้ไม่ได้ต่ออุปกรณ์ (เกิดจาก Sensor Noise) *(มีการเพิ่มโค้ดกรองข้อมูลเบื้องต้นแล้ว)*
   - `input.frequency` ติดค่าขยะ 211 Hz *(มีการเพิ่มโค้ดป้องกันแล้ว)*
   - โวลต์ Input / Output หายไปจากระบบ NUT เมื่อค่าเป็น 0 
2. **Innova Basic G2:**
   - การจัดเรียงไบต์สลับกัน ทำให้ค่าที่ได้มีโอกาสเพี้ยน เช่น โวลต์กระโดดไป 6000+ V
3. **ปัญหาอื่นๆ ที่รอการตรวจสอบ:**
   - ความแม่นยำของแบตเตอรี่ (battery.charge)
   - ความถูกต้องของอุณหภูมิ (ups.temperature)

---

## 🚀 แผนการตรวจสอบและปรับจูน (Validation Workflow)

เนื่องจากการเขียนโค้ดเพื่อลบค่า (Hardcode) อาจทำให้เกิดบั๊กซ้อนบั๊กใน UPS รุ่นอื่น วิธีที่แม่นยำและเสถียรที่สุดคือการ **"สแกน Raw Data ของ UPS ทุกรุ่น"** ออกมาดูเทียบกันไบต์ต่อไบต์

### สิ่งที่ต้องทำ (Action Items)
รบกวนเสียบ UPS แต่ละรุ่นเข้ากับบอร์ด Orange Pi (ทีละเครื่อง) และรันคำสั่งด้านล่างนี้เพื่อดึงข้อมูล Raw Data:

```bash
# 1. เข้าไปที่โฟลเดอร์รันโปรแกรม
cd /opt/enerex-ups

# 2. รันสคริปต์สแกนข้อมูลดิบ
sudo python3 -m ups_module.client
```

### ข้อมูลที่ต้องการ
เมื่อรันคำสั่งแล้ว โปรแกรมจะแสดงผล Raw Reports (เช่น `0x17`, `0x31`, `0x42`) รบกวนก๊อปปี้ Log ผลลัพธ์ที่ได้ทั้งหมด นำมาแปะเพื่อให้ทีมพัฒนา (ผม) ได้ดู:

- [ ] ข้อมูล Raw Data ของ **Innova Unity**
- [ ] ข้อมูล Raw Data ของ **Innova Basic G2**
- [ ] ข้อมูล Raw Data ของ **Offline UPS 2000D**
- [ ] ข้อมูล Raw Data ของ **MEC / รุ่นอื่นๆ (ถ้ามี)**

เมื่อได้ข้อมูลครบถ้วนแล้ว โค้ดดิคอดเดอร์ (Decoder) ใน `ups_module/core.py` จะถูกปรับจูนให้ตรงกับโครงสร้างฮาร์ดแวร์ของแต่ละรุ่นแบบ 100% ต่อไป
